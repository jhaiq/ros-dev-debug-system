## Q1. 需要机器人侧后端能力的功能（阻塞 Phase B）

rqt_bag（真实录制/回放）、rqt_top（节点 CPU/内存）、rqt_shell（远程终端）、rqt_py_console（rclpy 控制台）、rqt_launch 等功能在 rqt 中直接跑在机器人本机。本系统前后端目前**完全通过 rosbridge WebSocket 通信，没有任何在机器人侧执行进程/CLI 的通道**（代码中无 child_process）。rosbridge 协议无法实现：bag 文件读写、进程资源读取、shell 执行。

**方案**（在 backend 增加 ROS 环境内的后端模块，通过 ros2 CLI / Python API 实现）：
- 后端新增 `/api/bag/record|list|play|stop` 等 REST，内部调 `ros2 bag record/play`；
- `rqt_top` 后端读取 `/proc` 或 `ros2 daemon` 数据按节点聚合；
- `rqt_shell` 后端 WebSocket PTY；
- `rqt_py_console` 后端受控 rclpy REPL。

**需要确认**：
1. backend 是否部署在机器人（或与机器人同网络、有 ROS 环境的机器）上？
2. 是否允许后端在机器人侧执行 shell 命令？

> **人工确认**：（已确认）backend 部署在机器人侧或本机仿真环境，允许后端执行 `ros2 bag record/play`、`ros2` 进程查看、远程 shell/python 等命令。

## Q2. rqt_shell / rqt_py_console 的安全边界

远程 shell 等价于把机器人 root 权限暴露给 Web 端。需要人工决定：
- 是否仅在内网/可信网络开放？
- 是否需要登录认证（当前系统**完全无认证**）？
- 是否用白名单限制命令？

> **人工确认**：（已确认）先支持仅内网使用，后续再增强登录认证 / 命令白名单等能力。

## Q3. rqt 框架的"可停靠窗口 + 透视"如何映射到 Web（阻塞 Phase C）

rqt 的核心框架功能是：插件窗口可自由停靠/拆分/成标签页，布局可保存为透视并切换。本项目为固定侧边栏 + 单页路由结构。

**方案**：实现"工作台"页（`/workspace`），用 `react-mosaic` 类开源库（BSD，无安全漏洞）实现可拖拽分割/标签布局，透视（插件集合 + 布局 + 各插件配置）存 localStorage 并支持导入/导出 JSON。

**需要确认**：是否引入该布局库；工作台与现有单页路由的关系（并存 or 迁移）。

> **人工确认**：（已确认）引入工作台/透视系统，与现有单页路由并存。

## Q7. 无法 1:1 的精度差异（实现降级，请确认接受）

| 差异 | 原因 | 降级方案 |
|---|---|---|
| rqt_topic 的 Bandwidth 列 | rosbridge 传输的是 JSON 序列化消息，拿不到 DDS 线缆字节大小 | 用 JSON 序列化长度估算，标注"≈" |
| rqt_reconfigure 的 min/max/step 滑条 | rosapi 不提供参数描述符（param descriptor） | 按当前值类型推断编辑器，数值用普通输入框 |
| rqt_plot 取数 | rosbridge 只给 JSON 消息 | 字段路径表达式取数，等价 |

> **人工确认**：（已确认）接受。
